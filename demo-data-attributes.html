🚀 Annie Framework - Data Attributes vs Classes Demo

What are Data Attributes? Data attributes are HTML attributes prefixed with data- that allow you to store custom data on HTML elements without affecting styling or layout. They provide a clean separation between structure (HTML), presentation (CSS), and behavior (JavaScript).

📊 Before vs After Comparison

❌ Before: Class-Based Selection

<!-- Mixed concerns: classes for both styling and functionality -->
<div class="nav-container primary-nav route-container">
  <button class="nav-button route-btn active-route">Home</button>
  <button class="nav-button route-btn">About</button>
</div>

<!-- JavaScript selection -->
const routes = document.querySelectorAll('.route-btn');
const container = document.querySelector('.route-container');
  • ❌ Styling and functionality mixed
  • ❌ CSS changes can break JavaScript
  • ❌ Unclear which classes are for behavior

✅ After: Data Attribute Selection

<!-- Clean separation: classes for styling, data attributes for functionality -->
<div class="nav-container primary-nav" data-annie-component="route-container">
  <button class="nav-button" data-route="home" data-annie-role="route-enabled">Home</button>
  <button class="nav-button" data-route="about" data-annie-role="route-enabled">About</button>
</div>

<!-- JavaScript selection -->
const routes = document.querySelectorAll('[data-route]');
const container = document.querySelector('[data-annie-component="route-container"]');
  • ✅ Clear separation of concerns
  • ✅ CSS changes don't affect functionality
  • ✅ Self-documenting functional elements

📋 Data Attributes Overview

The Annie Framework uses a standardized data attribute system for element identification and functionality:

Framework Categories:
  • data-annie-component - Component identification (e.g., "route-container", "view-container")
  • data-annie-role - Functional role (e.g., "route-enabled", "navigation-container")
  • data-annie-state-* - Dynamic state management (e.g., "route-state", "loading-state")
  • data-annie-config-* - Configuration data (e.g., "api-endpoint", "trigger-config")

This approach provides:

  • Performance optimization through indexed lookups
  • Clear element relationships and hierarchies
  • Type-safe configuration storage
  • Framework-agnostic implementation

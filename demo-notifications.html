🚀 Annie Framework - SignalR Notifications Demo

📱 Real-time Notifications vs Polling

This demo shows how Annie Framework can use SignalR for real-time notifications instead of traditional polling.

⚡ SignalR Benefits:

  • Real-time: Instant notifications (no polling delay)
  • Efficient: Push-based, not continuous polling
  • Scalable: Server controls when to send updates
  • Bidirectional: Server can push data, client can send commands

🔄 Polling Issues:

  • Latency: Updates delayed by polling interval
  • Inefficient: Continuous requests even when no updates
  • Resource intensive: Each client polls independently
  • Scaling problems: More clients = more requests

📊 Performance Comparison

SignalR vs Polling Performance: Self-hosted SignalR: - Max connections: ~1,000-5,000 per server - Memory usage: ~4KB per connection - CPU overhead: High for broadcasting - Scaling: Requires backplane (Redis/SQL) - Cost: Server resources + maintenance Azure SignalR Service: - Max connections: 100,000+ per unit - Memory usage: Offloaded to Azure - CPU overhead: Minimal on app server - Scaling: Automatic - Cost: ~$1.50/1000 connections/month Polling Mode (30s interval): - Network requests: 120 requests/hour per client - Update latency: 0-30 seconds - Resource usage: High (continuous requests) - Scalability: Poor (N clients = N × 120 requests/hour) Migration Threshold: - Self-hosted: < 1,000 concurrent users - Azure SignalR: > 1,000 concurrent users - Consider at: 500+ users or multi-region needs

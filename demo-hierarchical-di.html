🏗️ Annie Framework - Hierarchical Dependency Injection Demo

🎯 Hierarchical DI Features

✅ Enhanced Capabilities:

  • Multi-Level Hierarchy - Parent/child containers
  • Service Scoping - Singleton, Scoped, Transient
  • Service Modules - Feature-based organization
  • Service Overrides - Child overrides parent
  • Interceptors - Before/after resolution hooks
  • Service Inspection - Runtime container analysis
  • Circular Detection - Dependency cycle prevention
  • Memory Management - Automatic scope disposal

🔄 Backward Compatible:

// Existing Annie code still works: const container = new DIContainer(); container.registerSingleton('logger', () => new ConsoleLogger()); const logger = container.resolve('logger'); // Plus new capabilities: const userModule = container .createModuleScope('users'); userModule.registerScoped('userService', (logger) => new UserService(logger), ['logger']);

📊 Service Lifetime Comparison

Lifetime Scope Instance Creation Memory Usage Best For
Singleton Application-wide Once per application Low Configuration, Database, Logging
Scoped Container scope Once per scope Medium Business services, Repositories
Transient Per resolution Every time resolved High Lightweight objects, Handlers

🎯 Usage Examples:

// Singleton - shared across entire app container.registerSingleton('config', () => new AppConfig()); // Scoped - one instance per module/request moduleContainer.registerScoped('userService', (config) => new UserService(config), ['config']); // Transient - new instance each time container.registerTransient('httpRequest', () => new HttpRequest());

🚀 Advanced Features Demo

Service Modules & Organization:

// Create reusable service modules const userModule = ServiceModuleBuilder .create('user-management') .addSingleton('userValidator', () => new UserValidator()) .addScoped('userService', (validator) => new UserService(validator), ['userValidator']) .addScoped('userRepository', (db) => new UserRepository(db), ['database']) .dependsOn('core-module') .build(); // Register in container container.registerModule(userModule);

Service Interceptors:

// Performance monitoring class PerformanceInterceptor { before() { this.startTime = performance.now(); } after(instance, context) { const duration = performance.now() - this.startTime; console.log(`${context.token} resolved in ${duration}ms`); return instance; } } // Register with interceptor container.register({ token: 'expensiveService', factory: () => new ExpensiveService(), lifetime: 'singleton', interceptors: [new PerformanceInterceptor()] });

Decorator Support (Optional):

@Injectable({ lifetime: 'scoped', tags: ['business-logic'] }) class UserService { constructor( @Inject('userRepository') private userRepo, @Inject('logger') private logger ) {} } // Auto-register decorated classes autoRegisterDecorated(container, [UserService, UserRepository]);

🏢 Real-World Architecture Example

Root Container (Application) ├── 🔧 AppConfig (singleton) ├── 📊 Database (singleton) ├── 📝 Logger (singleton) └── Module Containers ├── 👤 User Module │ ├── UserService (scoped) │ ├── UserRepository (scoped) │ └── UserValidator (singleton) ├── 🛒 Order Module │ ├── OrderService (scoped) │ ├── OrderRepository (scoped) │ └── PaymentService (scoped) └── 🌐 Request Containers (per HTTP request) ├── HttpContext (transient) ├── CurrentUser (scoped to request) └── RequestLogger (scoped to request)

💡 Benefits of This Architecture:

  • Service Isolation: Modules can't interfere with each other
  • Memory Efficiency: Request-scoped services auto-disposed
  • Testing Flexibility: Easy to override services for tests
  • Development Speed: Hot-swap services without restart
  • Performance: Singletons shared, scoped services cached per request
